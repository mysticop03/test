SYSTEM CHECKER

Problem

Manual/sequential inspection of store POS counters creates high effort, slow turnaround, and weak visibility into mismatches or offline systems.

Solution

Windows desktop tool with parallel SSH execution, automated version/file checks, URL probing, and instant pass/fail status tracking.

Impact

Fast audit execution, zero manual logins, counter-level pass/mismatch/offline visibility, and one-click recovery of failed machines.

Scale

Batch multi-store auditing with up to 100 POS counters per store and parallel store execution suitable for enterprise retail networks.

1. Solution

  • Centralized Verification: Automates version checks, file size validation, URL testing, and system health checks through a single Windows control application.
  • Parallel Processing: Uses multi-worker thread pools to audit stores and counters concurrently, completing full checks in seconds rather than hours.
  • Counter-Level Tracking: Tracks the exact status of every POS counter, providing clear visibility of matched versions, mismatches, and offline counters.
  • Automated Recovery: Isolates failed or offline counters and exports targeted re-test lists so operators never repeat already-completed checks.
  • Persistent State: Stores file paths, tender URLs, and configuration settings in local JSON so history is retained across application restarts.
  • Operational Efficiency: Eliminates manual SSH/terminal logins, prevents store router saturation, and exports formatted Excel (.xlsx) and CSV reports instantly.

2. End-to-End Process

  • Operator inputs target store IP or uploads an Excel / CSV store list.
  • Application validates target IP against authorized CIDR corporate subnets.
  • Operator selects inspection mode: Version Check, File Check, or Terminal Console.
  • Audit orchestrator submits parallel tasks across eligible Back Office and POS tills.
  • Remote SSH workers connect concurrently to verify delivery tokens, file sizes, or payment URLs.
  • Every counter reports its individual latency, operational status, and command output.
  • Reorder dispatcher sequences parallel results into deterministic Store-then-Till order.
  • Failed or offline counters are isolated and can be exported for immediate single-click re-testing.
  • The audit completes and outputs formatted Excel (.xlsx) and CSV reports.

3. Production Design

  • Bounded Concurrency: Dynamic sliding window limits store concurrency (1-10) and caps global SSH connections to 100, preventing router saturation on low-bandwidth store links.
  • Deterministic Hierarchy Ordering: Multi-threaded parallel probes are indexed and reordered in memory so that logs and table rows always display in sequential store order (Store → BO → Till 1..N).
  • Dual-Tier Security Model: Back Office servers (.15) are strictly 100% read-only with complete block on write utilities, while POS tills support safe whitelisted diagnostics.
  • Dedicated Status Categorization: Version checking cleanly separates matching versions, version mismatches, and offline counters into distinct dedicated columns.
  • 14-Inch Screen Optimization: High-performance Tkinter table viewport capped at 100 rows to ensure silky-smooth trackpad scrolling while 100% of audit data is preserved for export.
  • Smart Auto-Completion & History: Tab key autocompletes tender URL aliases (e.g. pine → full URL) and all typed paths automatically persist into config.json dropdowns.

4. Requirements

Requirement Specification
Operating System (App) Windows 10 / Windows 11 (64-bit)
Target Machines Ubuntu Linux 18.04 / 20.04 / 22.04 LTS (Store Back Office & POS Counters)
Runtime Environment Standalone Executable (.exe) — Zero Python or external dependencies required
Network Protocol SSHv2 (Port 22) via Paramiko over corporate WAN / VPN to authorized store subnets
Counter Capacity Up to 10 stores parallel; up to 100 POS counters per store (max 100 concurrent SSH)
Export Formats Native Microsoft Excel (.xlsx) and Comma-Separated Values (.csv)
Security Controls CIDR Subnet Whitelist, 100% Read-Only BO, Command Whitelist, Password Redaction
