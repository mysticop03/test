POS OPERATIONS HUB

Problem

Manually connecting to store BO servers and POS tills via terminal to check files, test URLs, or update configurations is slow, repetitive, and difficult to verify at scale.

Solution

A unified desktop application that connects to store systems in parallel to manage configurations, test URLs, verify release versions, and run routine daily commands.

Impact

Eliminates manual terminal sessions, catches version mismatches and offline counters instantly, and exports clean Excel reports for team and management review.

Scale

Multi-threaded architecture that processes all POS counters in a store concurrently and supports batch multi-store execution.

1. Core Capabilities

  • Property Management & Updates: Inspect any property key in configuration files across all tills, and update values in bulk with an automatic backup created before saving.
  • URL Check: Concurrently checks and returns HTTP status codes for essential store URLs (such as central servers, replication endpoints, payment tenders, ClearTax, etc.) directly from the till.
  • Version & File Check: Verifies application versions, file sizes, and last modified dates across BO and tills to ensure release consistency.
  • Routine Commands & Admin RBAC: Quick execution of pre-configured daily operational tasks, alongside a separate Role-Based Access Control (RBAC) mode for unrestricted command execution when required.

3. How the System Works in Detail

Parallel Connections (Why It Is Fast)

In standard operations, engineers connect to machines one after another, waiting for each command to finish before moving to the next. This application opens parallel SSH connections to the store BO and all POS tills simultaneously. Tasks across 15+ machines complete together in seconds rather than taking 20 to 30 minutes of manual waiting.

Automated Backups (Zero Risk File Edits)

Modifying configuration files manually carries the risk of typos that can stop a till from billing. Before this tool applies any property update, it automatically creates a timestamped backup copy on the remote machine. If an incorrect value is ever pushed, the previous working configuration can be restored immediately.

Direct Network URL Checks (Real Visibility)

Testing external URLs from an office laptop does not prove the store counters can connect to them. This tool commands each individual till to test payment gateway and central endpoints through its own local network. This immediately confirms whether that specific till can process payments or reach ClearTax.

Deterministic Ordering & Targeted Re-Tests

Parallel results can return out of order as fast tills respond before slower ones. The built-in sorter reorganizes incoming data into clean logical order (Store → BO → Till 1 to N). Furthermore, if any counter was offline or mismatched, operators can re-test just those failed machines with one click without repeating the rest.
