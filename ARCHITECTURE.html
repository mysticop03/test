🎛️ Interactive Operations Deck

Mode 1: Execute Command & HTTP URL Reachability (Wget / Curl)

Checks whether external payment gateways or microservices (e.g. Tata Digital, Razorpay, Pine Labs) are reachable from remote till network subnets.

💡
Smart HTTP Bash Wrapping: Whenever a command contains wget or curl, ssh_worker.py automatically wraps it in a bash subshell, redirects stderr (2>&1), adds a desktop Mozilla Firefox User-Agent, applies the user's frontend timeout, and pipes through an awk filter to extract a clean HTTP status code like 200 OK or 403 Forbidden!
Automated Bash Probe Wrapper Synthesized by ssh_worker.py 
bash -c "wget --spider -S -q -t 1 -T <timeout> \
  --user-agent='Mozilla/5.0 (X11; Linux x86_64; rv:109.0) Gecko/20100101 Firefox/115.0' \
  '<url>' 2>&1 \
  | grep -i 'HTTP/' | tail -1 \
  | awk '{print $2, $3, $4, $5}' \
  | tr -s ' '"

Mode 3: Generic Remote File Info & Timestamp

Inspects any arbitrary file path (e.g. SQLite database, shell script, configuration file) and returns existence, byte size, and last modified date.

Compound File Probe Command
if [ -f "/opt/pos/data/local.db" ]; then
    SIZE=$(stat -c %s "/opt/pos/data/local.db" 2>/dev/null || wc -c < "/opt/pos/data/local.db");
    MOD=$(stat -c %y "/opt/pos/data/local.db" 2>/dev/null | cut -d'.' -f1);
    printf "INFO|FOUND|%s|%s\n" "$SIZE" "$MOD";
else
    printf "INFO|MISSING|0|\n";
fi

Mode 4: Failure List Ingestion & Targeted Re-Audit

When an audit of 20,000 tills finishes with 25 failed tills, operators export audit_mismatched_tills.csv and can load it right back into the tool to re-scan ONLY those 25 tills.

💡
storage/store_reader.py detects the presence of the Till Name column in CSV/Excel and automatically switches into Re-Audit Direct Target Mode, completely bypassing subnet generation!

📄 Comprehensive File-by-File Deep Dive

⭐ core/ssh_worker.py
core/ssh_worker.py • 231 lines • SSH Transport & HTTP Wrapping
MOST FREQUENTLY CHANGED

The execution heart of the application. Opens SSH connections to remote Ubuntu POS tills, handles socket and channel timeouts, wraps custom commands with Mozilla User-Agent and HTTP extraction pipelines, and formats results into AuditResult.

Function SignatureRole & Responsibility
execute_till_probe(target, user, pwd, mode, params, timeout=30) Connects via SSH, runs the appropriate probe or command, records latency, parses output, and handles all network exceptions cleanly.
⏱️
Three Distinct Timeout Safeguards:
1. client.connect(timeout=timeout): TCP socket connection timeout.
2. wget -T <timeout>: Remote HTTP request response timeout.
3. client.exec_command(timeout=max(timeout+5, 20)): SSH channel buffer timeout.
⚡ If You Change This File... What It Affects:

• Changing HTTP code checks (if code == 200:) alters what displays in ui/components/results_table.py.
• Changing the User-Agent header affects whether external firewalls (e.g. Cloudflare / Tata Digital) allow or block till requests.
• Changing argument order in execute_till_probe will break worker thread calls in core/batch_orchestrator.py.

🔍 core/probe_engine.py
core/probe_engine.py • 365 lines • Shell Synthesis & Output Parser
CORE ENGINE

Builds POSIX shell probe commands executed on Ubuntu terminals in a single round-trip, handles byte sanitization, evaluates decimal and binary file size tolerances ($\pm0.3\text{ MB}$), and parses delimited string responses.

FunctionDescription
build_version_war_probe()Builds bash command that checks WAR file size and greps release version in one execution.
parse_version_war_output()Parses delimited WAR|size|date|PROP|val|line string and evaluates independent checks.
evaluate_size_match()Checks size deviation using dual decimal ($10^6$) and binary ($2^{20}$) byte calculations.
matches_delivery_version()Performs case-insensitive token-aware release version matching.
⚡ If You Change This File... What It Affects:

• Altering probe delimiter | will break parsing in ssh_worker.py.
• Changing tolerance in evaluate_size_match directly shifts tills between SUCCESS and SIZE_MISMATCH.

🛡️ core/safety_guard.py
core/safety_guard.py • 68 lines • Command Whitelist Sandbox
SECURITY SHIELD

Protects remote retail terminals from accidental or malicious destructive commands. Enforces a strict POSIX command whitelist, inspects all pipe segments independently, and blocks redirection operators.

⛔
Strict Whitelist Only: Commands like rm, mv, chmod, sudo, systemctl, and apt are blocked. Never add destructive tools to DEFAULT_WHITELIST!
Current Active Whitelist
DEFAULT_WHITELIST = [
    "uptime", "df", "free", "ps", "pgrep", "uname", "date",
    "cat", "head", "tail", "ls", "stat", "hostname", "wc",
    "wget", "curl", "lsusb", "grep", "awk", "tr", "sort", "uniq", "sed"
]
⚡ If You Change This File... What It Affects:

• Adding a command makes it immediately runnable across all 20,000 tills in Command mode.
• Removing a command causes it to be immediately rejected with BLOCKED_COMMAND.

🎯 core/batch_orchestrator.py
core/batch_orchestrator.py • 189 lines • Thread Pool & FCFS Scheduler
CONCURRENCY

Coordinates scanning across stores and tills. Batches execution store-by-store (default: 2 stores = ~26 tills simultaneously) to protect branch WAN routers, maintains strict First-Come, First-Served display ordering, and manages Pause, Resume, and Stop states.

FunctionRole
start_async(stores, mode, params, creds)Spawns daemon worker thread running _run_orchestration().
pause() / resume()Toggles execution pause using thread-safe threading.Event().
stop()Cancels active futures and stops submitting subsequent store batches.
_record_result(result)Updates AuditSummary metrics and posts RESULT event to UI.
⚡ If You Change This File... What It Affects:

• Event dictionary keys (event_type, data) must match what ui/app.py reads in _process_events().
• Tuning store_concurrency alters network socket usage on store WAN routers.

📦 models/target.py & models/result.py
models/ • 224 lines combined • Pure Domain Models
DATA STRUCTURES

Defines the foundational data models. TillTarget and StoreRecord calculate till IP addresses from subnets. AuditStatus, AuditResult, and AuditSummary encapsulate scan results.

💡
Till IP Subnet Resolution Rules:
• Loopback: 127.x.x.x ➔ points to 127.0.0.1.
• UAT 1-Till Rule: If till_count == 1 and full IP given ➔ uses full IP directly (no offset appended).
• Standard Subnet: 10.3.23. with offset 112 ➔ Till 01 is .112, Till 02 is .113, etc.
• Re-Audit Mode: If direct_targets is populated from failure CSV ➔ uses exact targets directly!
⚡ If You Change This File... What It Affects:

• Adding a status to AuditStatus requires updating ui/theme.py (color tag), metrics_bar.py (counter), filter_toolbar.py (button), and results_table.py.
• Changing StoreRecord.resolve_targets() affects how all till IPs are computed.

🛠️ Practical Developer Cookbook (8 Ready-to-Use Recipes)

Recipe 1: How do I add a new command to the safety whitelist? ▼

Open core/safety_guard.py, locate DEFAULT_WHITELIST around line 15, and add your diagnostic tool (e.g. netstat, ss):

core/safety_guard.py
DEFAULT_WHITELIST: List[str] = [
    "uptime", "df", "free", "ps", "pgrep", "uname", "date",
    "cat", "head", "tail", "ls", "stat", "hostname", "wc",
    "wget", "curl", "lsusb", "grep", "awk", "tr", "sort", "uniq", "sed",
    "netstat", "ss"  # <-- Added here
]
Recipe 2: How do I change what HTTP status codes count as SUCCESS? ▼

Open core/ssh_worker.py, locate the HTTP status evaluation block, and update the condition (e.g. to also treat 302 Redirect as success):

core/ssh_worker.py
# Change:
if code == 200:
    result.status = AuditStatus.SUCCESS
# To:
if code in (200, 302):
    result.status = AuditStatus.SUCCESS
    result.is_mismatch = False
Recipe 3: How do I change the Mozilla User-Agent header? ▼

Open core/ssh_worker.py, find the ua = ... definition around line 85, and customize the string:

core/ssh_worker.py
ua = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36"
Recipe 4: How do I add a new column to the Results Table and Reports? ▼

Follow these 4 steps:

  1. Add new_field: str = "" to AuditResult in models/result.py.
  2. Assign result.new_field = ... in core/ssh_worker.py.
  3. Add column name in ui/components/results_table.py inside set_mode() and include result.new_field in add_result().
  4. Add column header and value in storage/excel_exporter.py and storage/csv_exporter.py.
Recipe 5: How do I change the default till offset from 112 or count from 13? ▼

Simply edit config.json:

config.json
{
  "default_start_ip_offset": 101,
  "default_till_count": 10
}
Recipe 6: How do I change version matching rules? ▼

Open core/probe_engine.py and modify matches_delivery_version(expected, actual_version_or_line).

Recipe 7: How do I tune concurrency for low-bandwidth cellular store links? ▼

Open config.json and reduce store concurrency and worker limits:

config.json
{
  "store_concurrency": 1,
  "max_workers_per_store": 4,
  "connection_timeout_seconds": 45
}
Recipe 8: How do I customize colors or fonts in the UI? ▼

Open ui/theme.py and adjust color constants (e.g. COLOR_PRIMARY, STATUS_TAGS) or font tuples.
